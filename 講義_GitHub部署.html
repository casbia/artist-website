Chapter 01

什麼是 Git 和 GitHub？

Git 是「版本控制系統」：把每次修改都記錄下來，可以隨時回到過去的版本。就像文件的「無限復原」功能，但更強大。

GitHub 是「雲端的 Git 倉庫」：把 Git 管理的檔案同步到網路上。既可以備份，也可以讓別人看到，還能開啟 GitHub Pages 把網站公開上線。

1-1 核心概念一覽

術語白話解釋對應操作
Repository（Repo）一個專案的資料夾，Git 在裡面記錄所有歷史在 GitHub 建立新倉庫
Commit「存檔」：把目前的修改打包並加上說明git commit -m "說明"
Push「上傳」：把本機的 commit 傳到 GitHubgit push
Pull「下載」：把 GitHub 的最新版本同步到本機git pull
Clone「複製」：把 GitHub 上的 repo 下載到本機git clone 網址
Branch「分支」：平行開發不同版本的機制進階功能，本課程以 main 為主

Homebrew 是 macOS 的套件管理器，安裝後管理工具非常方便。

Chapter 03

設定 Git 基本資料

Git 每次 commit 都會記錄「是誰做的修改」。在開始使用之前，必須告訴 Git 你的名字和 Email。這個設定只需要做一次。

Terminal / Git Bash
# 1. 設定使用者名稱（換成你自己的名字） $ git config --global user.name "龍蝦俠" # 2. 設定 Email（換成你申請 GitHub 的 Email） $ git config --global user.email "lobster@artmail.com" # 3. 確認設定是否正確 $ git config --global --list ▸ 應看到以下輸出： user.name=龍蝦俠 user.email=lobster@artmail.com
--global 表示這個設定套用到你電腦上所有的 Git 專案。如果某個專案需要不同的名字/Email，可以在那個專案的資料夾裡執行不含 --global 的版本。

Chapter 04

申請 GitHub 帳號

Step 1

前往 GitHub 官網

🔗 https://github.com

點擊右上角的「Sign up」

Step 2

填寫註冊資料

  • Email address：填入你的電子郵件（建議與 Git 設定相同）
  • Password：設定強度足夠的密碼
  • Username：設定你的 GitHub 帳號名稱
    ⚠️ 這個名稱很重要！你的網站網址會是 https://你的帳號名稱.github.io
    建議使用：藝術家名稱英文版（如 lobsterman-art）
Step 3

驗證帳號

完成 GitHub 寄出的 Email 驗證連結，帳號就建立完成。

GitHub 帳號名稱（Username）一旦設定後雖然可以更改，但更改後舊的網址會失效。選擇前請仔細考慮。

Chapter 06

建立 Repository 並連結本機

Step 1

在 GitHub 建立新 Repository

  • 登入 GitHub，點擊右上角的「+」→「New repository」
  • Repository name：填入 你的帳號名稱.github.io
    例如：lobsterman-art.github.io
    ⚠️ 這個名稱格式是啟動 GitHub Pages 的關鍵！
  • Description：可選填，例如「龍蝦俠新媒體藝術家個人網站」
  • Public / Private：選 Public（公開，GitHub Pages 免費版需要）
  • 「Initialize this repository」：不要勾選（因為我們本機已有檔案）
  • 點擊「Create repository」

📌 Repository name 取名方式差異：完整說明

GitHub Pages 提供兩種不同類型的靜態網站，取名方式決定了你的網站 URL：

Repository name 類型 網站 URL
lobsterman-art.github.io
（帳號名稱 + .github.io）		 User Site（使用者網站） https://lobsterman-art.github.io/
根目錄，乾淨的網址
my-artist-site
（任意其他名稱）		 Project Site（專案網站） https://lobsterman-art.github.io/my-artist-site/
網址後面有 repo 名稱子路徑

❓ 只填帳號名稱（不加 .github.io）可以發佈靜態網頁嗎？

可以。 任何名稱的 repo 都能透過 GitHub Pages 發佈靜態網頁，不限於 帳號.github.io。

差異只在於網址結構：

  • 帳號名稱.github.io（User Site）
    → 網址：https://你的帳號.github.io/（根路徑，最乾淨）
    → 每個 GitHub 帳號只能有 一個 User Site
    → index.html 直接對應根網址，連結不需要加子路徑
  • 其他任意名稱（Project Site）
    → 網址：https://你的帳號.github.io/repo名稱/
    → 可以有 無限多個 Project Site
    → 所有頁面連結要考慮「子路徑」問題（如 CSS 路徑可能需要調整）

💡 龍蝦俠網站建議用哪一種？

建議使用 帳號名稱.github.io（User Site），原因：

  • 網址最簡潔，不帶子路徑（適合作為「個人主網站」）
  • 所有 HTML 的 CSS / JS / 圖片相對路徑不需要任何調整，直接上傳即可
  • 分享名片或作品集時只需說：帳號.github.io，一眼就記住
⚠️ 子路徑陷阱提醒：
若使用 Project Site（非 帳號.github.io），所有頁面的 <a href="about.html"> 仍然可以正常運作（相對路徑），但若你在 HTML 或 CSS 裡有寫「/css/style.css」這種以「/」開頭的絕對路徑，就會指到根域名而找不到檔案。本課程的龍蝦俠網站使用相對路徑（css/style.css），因此兩種方式都可以，但仍建議用 User Site。
Step 2

複製 Repository 網址

建立後頁面上會顯示 repo 的網址，複製它（格式如下）：

https://github.com/lobsterman-art/lobsterman-art.github.io.git
Step 3

在本機初始化 Git

開啟終端機，cd 到你的網站資料夾（Artist_Website），執行：

Terminal / Git Bash
# 1. 進入網站資料夾（Mac：替換成你的實際路徑） $ cd "/Users/你的名字/Desktop/ArtWeb/Artist_Website" # （Windows Git Bash 路徑範例） $ cd "/c/Users/darren/Desktop/ArtWeb/Artist_Website" ──────────────────────────────────────────────── # 2. 初始化 Git（在此資料夾建立 .git 隱藏資料夾） $ git init ▸ 成功輸出： Initialized empty Git repository in .../Artist_Website/.git/ ──────────────────────────────────────────────── # 3. 將預設分支改名為 main（與 GitHub 一致） $ git branch -M main ──────────────────────────────────────────────── # 4. 連結到 GitHub 上的 Repository # （把網址換成你自己 GitHub 上的 repo 網址） $ git remote add origin \ https://github.com/lobsterman-art/lobsterman-art.github.io.git ──────────────────────────────────────────────── # 5. 確認遠端連結是否正確 $ git remote -v ▸ 成功輸出（fetch 和 push 各一行）： origin https://github.com/lobsterman-art/lobsterman-art.github.io.git (fetch) origin https://github.com/lobsterman-art/lobsterman-art.github.io.git (push)

Chapter 07

第一次上傳：commit & push

Git 的上傳流程分三步：Add（暫存）→ Commit（存檔）→ Push（上傳）
就像寄包裹：先把東西放進箱子（add）→ 封箱貼標籤（commit）→ 交給快遞（push）。
Terminal / Git Bash（在 Artist_Website 資料夾內）
════════════════════════════════════════════════ STEP 1 ｜ 查看目前有哪些檔案需要上傳 ════════════════════════════════════════════════ $ git status ▸ 輸出（紅色代表尚未暫存的新檔案）： Untracked files: (use "git add <file>..." to include in what will be committed) index.html about.html ... ════════════════════════════════════════════════ STEP 2 ｜ Add：把所有檔案放進「暫存區」 （. 代表目前資料夾內的全部檔案） ════════════════════════════════════════════════ $ git add . # 確認暫存結果（綠色代表已暫存） $ git status ▸ 輸出： Changes to be committed: new file: index.html new file: about.html ... ════════════════════════════════════════════════ STEP 3 ｜ Commit：存檔，附上本次修改說明 -m 後面的字串就是說明（要有意義！） ════════════════════════════════════════════════ $ git commit -m "初次上傳：龍蝦俠個人網站完整版" ▸ 成功輸出： [main (root-commit) a1b2c3d] 初次上傳：龍蝦俠個人網站完整版 15 files changed, 2500 insertions(+) ════════════════════════════════════════════════ STEP 4 ｜ Push：推送到 GitHub -u 設定預設推送目標（第一次才需要） 之後只需要 git push 即可 ════════════════════════════════════════════════ $ git push -u origin main ▸ 成功輸出： Enumerating objects: 20, done. Counting objects: 100% (20/20), done. Writing objects: 100% (20/20), done. Branch 'main' set up to track remote branch 'main' from 'origin'.
遇到「Please sign in」的 GitHub 登入視窗：選擇「Sign in with browser」，在瀏覽器完成授權後即可自動繼續。
Push 成功後，前往你的 GitHub Repository 頁面（https://github.com/你的帳號/你的repo），應該可以看到所有上傳的檔案！

Chapter 08

開啟 GitHub Pages

Step 1

進入 Repository 設定

在你的 GitHub Repository 頁面，點擊上方的「Settings」分頁。

Step 2

找到 Pages 設定

在左側選單找到「Pages」，點擊進入。

Step 3

設定 Source（來源）

  • Source：選擇「Deploy from a branch」
  • Branch：選擇 main，資料夾選 / (root)
  • 點擊「Save」
Step 4

等待 1~3 分鐘，然後開啟網站！

重新整理 Pages 設定頁面，會看到：

Your site is live at https://lobsterman-art.github.io

點擊這個連結，你的龍蝦俠藝術家網站已經在網路上公開了！🎉

如果 Repository 名稱不是 帳號.github.io 的格式，網站網址會是：
https://你的帳號.github.io/Repository名稱/

Chapter 09

日常更新工作流程

網站上線後，每次修改都只需要三個步驟：

每次更新的標準流程
# 1. 查看本次修改了哪些檔案 $ git status ──────────────────────────────────────────────── # 2. 暫存所有修改 $ git add . ──────────────────────────────────────────────── # 3. 存檔，說明這次修改了什麼 $ git commit -m "更新：新增「光的語言」作品頁面" ──────────────────────────────────────────────── # 4. 推送到 GitHub（已設定 -u，直接 push 即可） $ git push ▸ 1~3 分鐘後，GitHub Pages 自動部署，網站更新完成！

9-3 常見問題 Q&A

問題解法
push 時出現「Please sign in」選 Sign in with browser，在瀏覽器授權 GitHub 帳號
